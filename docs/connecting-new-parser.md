# Подключение нового парсера к ViewHub

Чек-лист на примере подключения парсера **Citadel** (`citadel2000.ru`). Порядок шагов
важен: сначала конфигурация и экстрактор (они задают контракт данных), затем парсер,
сервисная сборка, UI и только потом тесты и документация.

---

## 1. Изучить сайт до написания кода

- Открыть живую страницу выдачи, например `https://citadel2000.ru/catalog/?q=замок`.
- Найти **реальный селектор карточки товара**. У Citadel это `.product-card`, ~30 карточек
  на страницу. Проверять селектор нужно в живом HTML, а не по предположению: старый
  селектор `sm-search-product` на сайте отсутствует.
- Проверить, что рядом с товарами нет ссылок категорий. Fallback «все `<a href>`»
  недопустим: он собирает разделы каталога (`/catalog/zamki/`) вместо товаров.
- Проверить пагинацию. У Citadel следующая страница — `?PAGEN_2=2&q=...`, иногда
  кнопка «Показать ещё» (`data-next-page`) вместо обычных ссылок.
- Проверить, какие поля реально доступны. У Citadel цена скрыта до авторизации,
  поэтому `current_price` часто остаётся `NULL`. Статусы наличия: «В наличии»,
  «Много», «Ожидается поставка», «Под заказ».
- Проверить отдельно страницу товара. Код товара в выдаче пуст, зато на странице
  товара есть `#number-field`, а бренд — в JSON-LD (`brand.name`). Значит нужен
  отдельный проход по карточкам.

## 2. Конфигурация: `src/parsers_config/<site>_config.py`

1. Наследоваться от `BaseDBParsingConfig` (не от `BaseConfig` — такого класса в проекте нет).
2. Описать бизнес-колонки в `BUSINESS_COLUMNS` в нативном SQL-формате SQLite.
3. Указать `DEDUP_COLUMN` — колонку для `ON CONFLICT` при UPSERT.
4. Реализовать `get_full_schema()`, объединив `SYSTEM_COLUMNS` и `BUSINESS_COLUMNS`.

```python
class CitadelConfig(BaseDBParsingConfig):
    BUSINESS_COLUMNS: ClassVar[Dict[str, str]] = {
        "item_id": "TEXT NOT NULL",
        "name": "TEXT NOT NULL",
        "code": "TEXT",  # Код товара (артикул) со страницы товара
        "url": "TEXT",
        "brand": "TEXT",
        "availability": "TEXT",
        "description": "TEXT",
        "current_price": "REAL",
    }
    DEDUP_COLUMN: ClassVar[str] = "item_id"

    @classmethod
    def get_full_schema(cls) -> Dict[str, str]:
        return {**cls.SYSTEM_COLUMNS, **cls.BUSINESS_COLUMNS}
```

**Ключевое правило:** ключи `BUSINESS_COLUMNS` должны **в точности** совпадать с ключами
словарей, которые отдаёт экстрактор. `DatabaseManager.save()` берёт значения строго
по именам колонок схемы. Расхождение даёт `NULL` в полях и `IntegrityError` на
`NOT NULL` — в БД не попадёт ни одна строка.

Если схема изменилась после первого запуска, удалять таблицу не нужно:
`ensure_table()` сравнивает её с `PRAGMA table_info` и добавляет недостающие
колонки через `ALTER TABLE`. Старые строки при этом сохраняются (новые колонки
получают `NULL`). Ограничения `NOT NULL`/`UNIQUE` при такой миграции не
накладываются — SQLite не позволяет добавить их в непустую таблицу без DEFAULT.

## 3. Экстрактор: `src/extractors/<site>_extractor.py`

1. Наследоваться от `BaseExtractor`, принимать `config` в `__init__`.
2. Парсить карточки через найденный селектор. Если карточек нет — вернуть `[]`,
   а не падать и не переходить на fallback со всеми ссылками.
3. Возвращать список словарей с теми же ключами, что и в конфиге.
4. Идентификатор товара брать из надёжного источника. У Citadel `#number-field`
   в HTML пуст до авторизации, поэтому `item_id` берётся из последнего сегмента URL:
   `/catalog/.../zamok-navesnoy-pd-21-h-blister-apeks/` → `zamok-navesnoy-pd-21-h-blister-apeks`.
5. Вести `seen_hrefs` на уровне экземпляра экстрактора, чтобы не дублировать товары
   между страницами одного прогона; предусмотреть `clear_seen()`.
6. Приводить статусы наличия к единому виду через отдельную функцию/таблицу.
   Порядок маппинга важен: «нет в наличии» содержит подстроку «в наличии», поэтому
   более конкретный статус проверяется первым.
7. Для полей, которых нет в выдаче, сделать отдельный метод `extract_detail_data()`.
   У Citadel он достаёт:
   - `code` из `#number-field` (fallback — `.number-copy`, `.number`,
     `.product-brand-part`). Подпись «Арт.:» убирается регулярным выражением;
   - `brand` из JSON-LD объекта `Product` → `brand.name`. Подпись «Бренд» из выдачи
     — это заглушка, её нужно отфильтровывать, иначе в БД везде запишется «Бренд».
8. Импорты только абсолютные: `from src.my_exceptions.exceptions import ...`,
   `from src.core.base_classes import ...` (относительный `my_exceptions` ломает
   запуск `python main.py`; pytest маскировал эту ошибку через `pythonpath`).

## 4. Парсер: `src/parsers/<site>_parser.py`

1. Наследоваться от `BaseParser`, принимать `config`, `extractor`, `manager` через конструктор.
2. `run_parsing()` — генератор, отдающий пачки товаров по страницам.
3. Сохранение делает **сам парсер** (`self.manager.save(new_items)`), как в
   GoldenApple и Gardarika. `ParserWorker` сохранением не занимается.
4. В `_build_url()` кодировать ключевое слово через `quote_plus()` и добавлять
   параметр страницы (`&PAGEN_2=N`).
5. Ждать появления именно карточек (`wait_for_selector(".product-card")`), а не
   любых ссылок `/catalog/` — они есть и в меню категорий.
6. Останавливаться после `EMPTY_PAGES_LIMIT = 2` пустых страниц подряд;
   ограничить обход `MAX_PAGES = 150`.
7. **Обязательно `try/finally`**: закрывать страницу → контекст → браузер.
   Иначе при отмене или ошибке остаётся процесс Chromium.
8. Отмена: `BaseParser.cancel()` вызывает переопределяемый `_on_cancel()`.
   В хуке только поднять флаг и сообщить пользователю; закрывать объекты Playwright
   из потока GUI небезопасно — они принадлежат потоку воркера. Ресурсы закрываются
   в `finally`. Проверка флага — на каждой итерации цикла.
9. Проход по карточкам делать отдельно от выдачи: после разбора страницы списка
   открывать страницу каждого товара, обогащать `code`/`brand` и сохранять товар
   сразу (`self.manager.save([item])`), чтобы не потерять данные при отмене посреди
   страницы. Если карточка недоступна — сохранять то, что есть из выдачи.
10. Статус в лог-панель отправлять через `progress_callback`, если он подключён воркером.

## 5. Сервисный слой: `src/service_modules/parsing_service.py`

1. Добавить импорты трёх новых классов в начале файла.
2. Написать функцию сборки с обязательным параметром `obj`:

```python
def prepare_parsing_citadel(obj) -> None:
    config = CitadelConfig()
    extractor = CitadelExtractor(config)
    obj.manager = DatabaseManager()
    obj.parser = CitadelParser(config=config, extractor=extractor, manager=obj.manager)
```

Зависимости передаются через конструктор, поэтому парсер не знает ни про SQLite,
ни про Qt и тестируется без графического интерфейса.

---

## 6. UI: `src/windows_pq.py`

1. Импортировать `prepare_parsing_citadel`.
2. В `show_parsing_page()` вызывать сборку **с `self`**:
   `prepare_parsing_citadel(self)`. Вызов без аргумента даёт
   `TypeError: missing 1 required positional argument: 'obj'`.
3. Указать стартовый URL окна парсинга:
   `self.target_url_input.setText("https://citadel2000.ru/")`.

Переключение площадок из интерфейса не предусмотрено: страница «Парсинг» жёстко
настроена на Citadel. Чтобы использовать другой парсер, меняется вызов в коде.

## 7. Тесты

1. Создать `tests/test_citadel.py`:
   - схема конфига = системные + бизнес-колонки, `DEDUP_COLUMN` в схеме;
   - ключи словаря экстрактора совпадают с `BUSINESS_COLUMNS`;
   - парсинг карточек: все поля, игнорирование ссылок категорий, дедупликация;
   - маппинг статусов, пустая страница;
   - `extract_detail_data()`: код из `number` с удалением «Арт.:», бренд из JSON-LD,
     фильтрация заглушки «Бренд»;
   - обогащение карточек в `run_parsing()` и закрытие страниц товара;
   - `_build_url()` для первой и последующей страниц;
   - `cancel()` вызывает `_on_cancel()` и поднимает флаг;
   - `run_parsing()` сохраняет данные и закрывает браузер (моки Playwright);
   - `prepare_parsing_citadel()` собирает конфиг/экстрактор/менеджер/парсер
     (все четыре зависимости нужно замокать, включая `CitadelConfig`).
2. Обновить `tests/test_windows_pq.py`: ожидаемый URL и цель мока
   `src.windows_pq.prepare_parsing_citadel`.
3. Убрать новые файлы из `omit` в `pyproject.toml` — иначе покрытие не контролирует
   подключённый парсер.

## 8. Проверка перед коммитом

```bash
poetry run ruff check . --output-format concise
poetry run python -m pytest tests/ -q
poetry run python main.py          # убедиться, что приложение стартует
```

Ожидаемый результат: линтер без замечаний, все тесты зелёные, приложение запускается.
Дополнительно сверить статус площадки в `README.md` и упомянуть новый парсер в
разделе «Мультипарсерная архитектура».
