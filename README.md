# 💻 ViewHub

ViewHub — десктопное кроссплатформенное приложение для безопасной интеграции с внешними источниками данных через API и гибкого многопоточного парсинга с инкрементальным сохранением данных в СУБД SQLite. Программа отображает полученную информацию в основном окне, ведёт потокобезопасное логирование процессов в отдельной панели и предоставляет модульную расширяемую архитектуру для сбора, обработки и аналитики данных.

---

## 🎯 Основные возможности

* **Интеграция с Django API**: Безопасное подключение к удаленному бэкенду на VPS по HTTP-протоколу для авторизации пользователей и обмена системными данными.
* **Многопоточный асинхронный парсинг**: Архитектура включает фоновые потоки `QThread`, полностью исключающие зависание GUI-интерфейса во время тяжелых сетевых операций и ожидания браузера.
* **Отказоустойчивый поштучный UPSERT**: Постраничный сбор данных с немедленной записью каждого товара на диск. Использование технологии **SQLite WAL (Write-Ahead Logging)** и режима `synchronous = OFF` гарантирует максимальную скорость дисковых операций и сохранность данных при внезапном падении браузера или появлении капчи.
* **Умный контроль пагинации и дубликатов**: Перед глубоким обходом страниц парсер делает один быстрый групповой запрос `WHERE IN` к БД, выгружая словарь существующих товаров с номерами их страниц. Это позволяет **парсить только новинки**, полностью игнорировать старые карточки и мгновенно останавливать работу при зацикливании или выходе на уже пройденный хвост каталога.
* **Раздвижной многозонный интерфейс**: Главное окно разделено на три независимые зоны (Взаимодействие/Авторизация, Панель вывода данных, Панель логирования) с возможностью динамического изменения их размеров на лету.
* **Централизованное логирование**: Потокобезопасный вывод системных логов в реальном времени прямо на экран с параллельной записью лог-файлов на диск. Ошибки автоматически форматируются до первой строки для чистоты вывода.

## 🛠️ Стек технологий

* **Язык программирования**: Python 3.14+
* **Автоматизация браузера**: Playwright (С Chromium, эмуляцией плавного скролла для Nuxt 3 и изоляцией пользовательских профилей)
* **СУБД**: SQLite3 (Встроенная пакетная поддержка, WAL-режим транзакций, автоинкремент)
* **Графический интерфейс (GUI)**: PyQt6 (QtCore, QtWidgets, QStackedWidget)
* **Сетевое взаимодействие**: Requests (HTTP-запросы к API Django)
* **Анализ парсинга**: BeautifulSoup4 (с поддержкой высокоскоростного парсера `lxml`)
* **Менеджер зависимостей**: Poetry (v2.0+)

## 📦 Архитектура и структура проекта

Проект спроектирован по модульному принципу со строгим соблюдением SOLID, паттерна «Стратегия» и полной изоляцией слоя баз данных и парсинга от графического интерфейса:

* **`main.py`** — Главная точка запуска приложения и инициализации глобального логгера.
* **`src/windows_pq.py`** — Сборка графического интерфейса `MainWindow`, управление слоями, сигналами и слотами.
* **`src/exceptions.py`** — Изолированный слой кастомных исключений (например, `ExceptionStopParser`), предотвращающий циклические импорты (Circular Imports).
* **`src/core/base_classes.py`** — Набор базовых абстрактных интерфейсов системы (ABC):
  * `BaseDBParsingConfig` — Абстрактный контракт конфигурации. Хранит системные колонки (`id`, `created_at`, `session_id`), дефолтные `TABLE_CONSTRAINTS` и обязывает переопределять схему.
  * `BaseExtractor` — Определение логики извлечения данных из HTML (BeautifulSoup).
  * `BaseParser` — Интерфейс управления обходом страниц, сетевой логикой и механизмами экстренной отмены (`cancel`).
  * `BaseSaver` — Описание общей стратегии сохранения данных.
* **`src/savers/sqlite_saver.py` (`SQLiteSaver`)** — Универсальный сервисный класс для работы с БД. Автоматически генерирует безопасные имена таблиц, валидирует схемы, накладывает индексы `UNIQUE` на колонки дедупликации, выполняет точечную IN-проверку страниц и осуществляет пакетный/поштучный `UPSERT`.
* **`src/parsers_config/golden_apple_config.py` (`GoldenAppleConfig`)** — Декларативный класс, описывающий бизнес-колонки косметики (`brand`, `price`, `in_stock`, `page_number`) в нативном SQL-формате для SQLite, задающий ключ дедупликации `DEDUP_COLUMN = "item_id"`.
* **`src/parsers/golden_apple_parser.py` (`GoldenAppleParser`)** — Управляющее ядро парсера Золотого Яблока. Реализует обход пагинации, плавный скролл, поштучное обогащение карточек детальными данными (описание, применение, страна) и применяет алгоритм остановки на основе сравнения страниц базы данных.
* **`src/parsers/golden_apple_extractor.py` (`GoldenAppleExtractor`)** — Извлечение базовых данных из листинга и глубоких характеристик со страницы товара с приведением типов под требования СУБД (`REAL`, `INTEGER`).

## 🚀 Установка и запуск

Для управления окружением и зависимостями проекта требуется утилита [Poetry](https://python-poetry.org).

### 1. Подготовка репозитория
Клонируйте проект и перейдите в рабочую директорию:
```bash
git clone https://github.com
cd ViewHub
```

### 2. Установка зависимостей и драйверов
Poetry автоматически создаст изолированное виртуальное окружение и установит все пакеты (PyQt6, Playwright, lxml, Requests), зафиксированные в конфигурации:
```bash
poetry install
```

После установки зависимостей необходимо один раз инициализировать системные бинарные файлы браузеров для Playwright:
```bash
poetry run playwright install chromium
```

### 3. Запуск приложения
Запустите графический интерфейс в контексте виртуального окружения Poetry:
```bash
poetry run python main.py
```

## 💡 Использование

1. **Главное меню**: При старте приложения нажмите на кнопку **«АВТОРИЗАЦИЯ»** в Зоне 1 для подключения к Django API или выберите интересующий модуль парсинга.
2. **Ввод данных**: Задайте ключевое слово (каталог/слаг раздела) для поиска на целевой площадке.
3. **Парсинг и дедупликация**: Нажмите кнопку **«Старт»**.
   * Выбранный сейвер проверит существование файла базы данных `data/viewhub.db` и автоматически создаст подраздел (таблицу) с уникальным именем, если её не было.
   * Приложение сгенерирует уникальный `session_id` для текущего запуска, чтобы разграничивать историю сборов.
   * Парсер начнет постраничный обход. Система автоматически отфильтрует товары, которые уже есть в базе данных: **старые товары будут пропущены без открытия вкладок**, а для новых запустится глубокий обход карточек поштучно.
   * В Зоне 3 (Логирование) будут выводиться потокобезопасные системные логи (`INFO` или `ERROR`) о создании таблиц, анализе страниц и прогрессе сбора характеристик.
4. **Остановка**: Вы можете прервать парсинг в любой момент кнопкой **«Стоп»** — браузер корректно завершит сессию, закрыв вкладки, а все поштучно сохраненные к этому моменту новинки гарантированно останутся в базе данных.
